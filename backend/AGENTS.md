## Coding rules for service implementation

When implementing service methods:

- **DTOs are immutable records**. Do not modify a DTO after creation. Create a new one instead.
- **When creating a new entity** (POST), do NOT set the ID field. The database generates it via `GENERATED BY DEFAULT AS IDENTITY`. Convert the DTO to an entity, save it, then convert back to a DTO.
- **When updating an entity** (PUT), load the existing entity from the database, update its fields from the DTO, save it, then convert back to a DTO.
- **When deleting an entity** (DELETE), just call `repository.deleteById(id)`. No DTO conversion needed.
- **Use `var` for local variables** where the type is obvious (e.g., `var entity = repository.findById(id).orElseThrow(...)`).
- **Use `orElseThrow`** instead of `isPresent()`/get() for optional values in service methods.

Example for creating a new entity:
```java
public PostEntityDto createPost(PostEntityDto request) {
    var entity = request.toEntity();
    entity.setId(null); // ensure ID is null so the DB generates it
    var saved = repository.save(entity);
    return PostEntityDto.from(saved);
}
```
